# Lote incremental SGS11 → Google Cloud (NIVON)

Data: 23/10/2026. Branch extraída diretamente da `main` mais recente, sem incorporar as PRs extensas #147/#163.

## Resultado implementado

`src/nivon/sgs11_gcp.py` contém uma rota executável para a série **11 do SGS/BCB (taxa Selic diária)**:

1. Verificar projeto/dataset/bucket e tabela **particionada por `data_referencia`**, por meio de `preflight_gcp_fontes.verificar_nuvem`.
2. Consultar endpoint HTTPS fixo `https://api.bcb.gov.br/dados/serie/bcdata.sgs.11/dados/ultimos/1?formato=json`; rejeitar redirect, HTML, resposta grande, JSON duplicado e datas futuras.
3. Normalizar estritamente valor como **percentual ao dia**, jamais meta anual ou CDI; `data_publicacao=None` por falta de comprovação e `data_referencia` extraída da própria série.
4. Persistir JSON oficial RAW por SHA no ledger SQLite existente `ingestao_fontes_reais.gravar_lote`, mantendo versões revisadas.
5. Arquivar RAW no GCS por `arquivo_raw_gcs.arquivar_gcs` com chave imutável e snapshot_id.
6. Exportar somente esse snapshot com `exportar_jsonl`; arquivar JSONL e manifesto recuperáveis usando `lote_cloud_recuperavel.arquivar_stage`.
7. Executar `carga_bigquery_fontes.executar_carga` (MERGE idempotente em `nivon_observacoes`).
8. Confirmar RAW e amostras reais no BigQuery com `verificacao_cloud_fontes.verificar_publicacao` antes de declarar sucesso.

Não adiciona outro SDK, arquivador RAW, carregador BQ, nova base de dados ou infraestrutura paralela. Não entrega dados aos indicadores editoriais automaticamente.

## Como operar

Planejamento inerte:

```bash
python -m nivon.sgs11_gcp
```

Com as configurações Cloud e os direitos realmente homologados, o workflow manual **NIVON - BCB SGS11 para GCS BigQuery com readback** poderá executar o mesmo comando `python -m nivon.sgs11_gcp --executar` em `main`.

Variáveis (em GitHub Actions): `NIVON_GCP_PROVIDER`, `NIVON_GCP_SERVICE_ACCOUNT`, `NIVON_BQ_PROJECT`, `NIVON_BQ_DATASET`, `NIVON_GCS_BUCKET`, `NIVON_SGS11_EVIDENCIA_USO`. Gates independentes: `NIVON_SGS11_GCP_WRITE_APPROVED=true`, `NIVON_RAW_ARCHIVE_APPROVED=true`, `NIVON_ZERO_COST_BQ_APPROVED=true`. Para permitir agendamento diário depois de validação de duas execuções, `NIVON_SGS11_E2E_VERIFIED=true`.

O workflow requer `main` e ambiente `nivon-gcp-producao`. Autentica via WIF, sem chave JSON permanente. Gate `ZERO_COST` é aprovação de orçamento, não garantia de fatura nula. É necessário confirmar permissões de escrita, limites e eventual custo de cada job.

## Critério de conclusão em produção

- Job com WIF executa **sem pular etapas**.
- Resposta BCB atual, com valor e data realmente publicados.
- Arquivo GCS original e stage conferidos por hash/snapshot_id.
- Manifesto SHA disponível para replay sem runner original.
- BigQuery retorna amostras do mesmo `dataset_id`, `fingerprint` e data de referência.
- Segunda execução confirma ausência de revisão artificial/duplicata.
- Não houve promoção de dado incerto ou publicação externa automática.

## Evidência e limites

`tests/test_sgs11_gcp.py` cobre E2E sintético com injeção das dependências de nuvem, gates, replay, falhas de origem e bloqueio de falsa confirmação. **A aprovação do CI não é comprovação de execução GCS/BQ real.** Em 23/10/2026, WIF e leitura de metadados de Google Cloud já foram confirmados na `main` pelo run 39980530880, mas nenhuma carga de SGS11 foi executada por este lote.

CONAB/IMEA/CEPEA já possuem adaptadores próprios na `main`; usar `agro_origem_gcp`, `agro_staging_bigquery` e `coletar_agro_google_cloud.py` para esses temas. As PRs legadas #147/#163 não devem ser mescladas em conjunto sem reconciliação, pois usam outro contrato BigQuery e possuem recursos duplicados.
